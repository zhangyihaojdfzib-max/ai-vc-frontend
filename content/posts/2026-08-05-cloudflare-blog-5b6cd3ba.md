每个组织都有自己的使命，即存在的理由。组织将其使命——连同其术语、流程、系统、标准和工作方式——传递给员工。员工则将这些背景信息与自身经验相结合，朝着使命努力。

工作的形式多种多样，从代码、文档和幻灯片，到人际关系，再到现实世界中的成果。

其中有些工作是直截了当的：代码要么能运行，要么不能。过去几年里，Agent（智能体）一直在利用这种反馈循环为开发者生成“能运行”的代码。但我们其他人呢？

将同样的杠杆效应带给组织中的其他成员是一个更棘手的问题。Agent（智能体）需要理解公司的背景信息，并且能够访问人们工作所使用的系统。他们需要将这些背景信息和访问权限转化为推动组织朝着使命前进的工作成果。

这就是我们创建 Cloudflare OS 的原因。它为每个人提供了一个围绕其公司构建的 Agent（智能体）和工作空间：包括公司的运作方式、知识储备以及所依赖的系统。

今年五月，我们让 Cloudflare 的每位员工都能使用第一版 Cloudflare OS。来自各个职能部门的数千人（其中许多人并非工程背景）每天都在使用它来创建文档和幻灯片、自动化重复性任务，以及构建小型应用来可视化数据并辅助工作。

Cloudflare OS 还为每个人提供了一个由 Cloudflare 各团队构建的共享背景知识和技能库。它将我们的术语、流程以及完成重复性工作的最佳实践捕获为 Agent（智能体）可以遵循的指令。当一个人找到了更好的方法时，其他人也都可以使用。

今天，我们开源了新版本的 Cloudflare OS。任何组织都可以部署它，将其连接到内部系统，并将其打造成自己的平台。

## 我们从第一版中学到了什么

我们今天开源的 Cloudflare OS 基于我们在内部运行第一版时所获得的经验教训，我们的首席信息官 Sam Rhea 在他的博客文章中介绍了这一历程。

第一版侧重于个人通过私有工作空间与 Agent（智能体）协作。应用是静态的，而不是连接到内部系统的实时软件，而且大多数确定性任务仍然需要再次运行 Agent（智能体）技能并消耗更多的模型 Token。

协作暴露了一个更根本的挑战。访问 MCP 服务器告诉我们 Agent（智能体）可以调用哪些工具，但无法告诉我们 Agent（智能体）观察到了哪些底层资源。一旦人们开始共享工作空间、应用和输出，我们就需要确保协作不会泄露任何人无权查看的信息。

我们基于新的基础重新构建了 Cloudflare OS 来解决这些问题。安全性必须是平台的一部分，而不是每个构建应用或使用 Agent（智能体）的人都必须正确实施的事情。

最终成果是一个旨在归属于运行它的公司的平台。您可以自定义界面、连接您的工具，并添加能够反映您组织运作方式的技能和背景知识。

## 认识 Cloudflare OS

Cloudflare OS 从浏览器中的对话开始，就像许多其他 AI 工具一样。它的不同之处在于，每次对话都基于您的组织精心整理的背景知识和技能。为您的空间设定一个目标，它就可以利用这些知识，并使用您的组织已经在使用的工具和数据来实现该目标。

![BLOG-3379 2.png](/images/posts/4f331cccbfec.jpg)

Cloudflare OS 由三部分组成：

- 一个 Agent（智能体）工作空间，基于您的公司整理的背景知识和技能，并配备一个隔离的运行时环境，Agent（智能体）可以在其中编写和运行代码。
- 一个新的安全和治理框架，用于安全访问内部数据和服务。
- 一个个人可修改应用平台，人们可以构建、共享并持续修改这些应用。

从对话开始的内容可以演变成文档、应用或持续执行工作的流程。

## 为贵公司每个人打造的 Agent（智能体）工作空间

Agent（智能体）工作空间旨在供组织中的每个人使用。您可以在浏览器中与之交互，因此您不必是开发人员，也不必知道如何使用终端。

工作空间结合了 Agent（智能体）会话、持久状态、输出和文件、资源访问，以及一个 Agent（智能体）可以编写和运行代码的隔离运行时环境。

它们预装了您的团队或公司收集整理的背景知识和技能。不再需要为每项任务重新发明轮子——如果您的团队中有人找到了最佳方法，每个人都可以受益。人们不再需要在每次开始任务时向模型解释相同的流程、术语和最佳实践。

您可以做的一些事情：

### 研究和提问

让工作空间使用公司背景信息和您提供给它的资源来研究某个主题。Agent（智能体）可以编写代码来搜索、过滤、连接和分析信息，而不是将整个数据集拉入模型的上下文窗口。

### 创建文档、幻灯片和电子表格

工作空间可以将其研究转化为您可以继续编辑的文档、演示文稿或电子表格。这些输出不必是静态文件。它们可以保持与实时数据的连接，随着数据源的变化而更新，并且仍然可以导出为熟悉的格式或服务，例如 Google Drive。

### 为您的团队创建协作式、互联的应用

当文档或电子表格不够用时，Agent（智能体）可以构建一个具有自己的界面、逻辑和状态的应用。该应用可以使用已连接的公司资源，并支持多人协作。

### 运行确定性工作流

并非每项工作都需要完整的 Agent（智能体）会话。许多工作是已知的步骤序列，其中只有一两个地方需要判断。工作空间可以将这些工作转化为大多是确定性的工作流，对可预测的步骤使用代码，仅在需要增加价值的地方使用模型。工作流可以按需运行、按计划运行，或在连接系统中发生事件时运行。

Cloudflare OS 通过 Gatekeeper（详见下文安全部分）为 Agent（智能体）和应用提供对记录系统的受治理访问。它还通过 MCP 服务器门户支持您的组织已在使用的现有模型上下文协议（MCP）服务器。

## 一个新的安全和治理框架，用于安全访问内部数据和服务

当人们开始在工作中尝试 AI 时，他们的首要请求之一通常是获取公司系统的 API 密钥。这很合理：如果 AI 无法访问人们工作所用的系统，那么它在工作中就没什么用处。

但是，将 API 密钥交给个人和 Agent（智能体）是危险的，并且无法扩展。密钥通常提供广泛、长期的访问权限，难以限制、安全共享和审计。

MCP 为 Agent（智能体）提供了一种使用这些系统的更好方式。MCP 服务器可以持有凭证并公开一组定义好的工具，而不是直接将密钥交给 Agent（智能体）。但控制 Agent（智能体）可以调用哪些工具只是第一步。仅靠 MCP 无法告诉我们 Agent（智能体）观察到了哪些底层资源。Agent（智能体）可以跨系统组合信息，将其发送到限制较少的地方，或者通过应用和输出将其暴露给可能无权查看原始资源的人。授权必须考虑数据的后续流向。

### Agent（智能体）从无访问权限开始

Cloudflare Access 控制谁可以进入 Cloudflare OS。在内部，每个 Agent（智能体）和应用一开始都没有任何访问权限。Agent（智能体）可以请求访问特定资源，您可以授予或拒绝该请求。生成的代码会将该资源作为类型化绑定接收：

```
const issues = await env.PROJECT.listIssues({
  teamId: "ENG",
  state: "open",
});
```

`env.PROJECT` 是一个能力，代表在特定策略下使用特定资源的权限。凭证与 Agent（智能体）和任何生成的代码完全隔离。

服务器代码在禁用全局出站网络的动态 Worker 中运行。客户端代码在浏览器的沙箱框架中运行。除非通过你明确提供的能力，否则两者都无法访问互联网。

### 守门人（Gatekeeper）管理资源和操作

守门人是一个特定于服务的 Worker，位于 Cloudflare OS 和外部服务之间。它理解服务的 API、其资源以及可对其执行的操作。

让 Agent 访问你的整个 GitHub 账户可能过于宽泛。守门人可以赋予它访问单个仓库的权限，允许其读取 Issue 但不读取源代码，屏蔽特定字段，应用速率限制，并在合并拉取请求前要求审批。

Agent 及其应用看到的是一个精简的 TypeScript API。守门人处理 OAuth、持有凭证、执行策略、记录读取内容，并调解任何具有外部可见副作用的事务。

![BLOG-3379 3.png](/images/posts/6f6ae0e644b3.jpg)

### 策略遵循 Agent 所见内容

仅控制初始读取是不够的。例如，假设 Agent 读取了数据仓库中的敏感表，并用它生成实时仪表板。共享仪表板绝不能成为与无法直接访问该表的人共享该表的方式。

Cloudflare OS 记录 Agent 观察到的每个资源。这些观察记录始终与 Agent 及其工作相关联。当其他人尝试打开工作区、与 Agent 交互或查看其产出时，守门人会验证该人对所观察资源的访问权限。

![BLOG-3379 4.png](/images/posts/83b6eb55e937.jpg)

同样的观察日志用于制定策略，以确定 Agent 何时可以发起外部请求。读取敏感数据可能会阻止 Agent 向某些数据源写入数据、邀请新的协作者、将工作移交给另一个 Agent 或发起出站请求。

使用 Agent 或构建应用的用户无需担心犯下这些错误。该平台现在可以处理这些问题。

## 一个用于构建和共享个人化、可修改应用的平台

大多数生产力套件提供固定的应用集：文档、电子表格和演示文稿。在 Cloudflare OS 中，每个“文件”都可以是独立的应用，由 Agent 为一个人、一个项目或一个团队编写。

这些并非需要导出并部署到其他位置的原型。每个应用都是全栈应用，包含客户端代码、服务器代码、API 和持久化状态。应用默认是私有的，但可以像文档一样共享。

### 每个应用都是一个 Worker

当你要求工作区构建应用时，Agent 会编写两个部分：

- 在浏览器中渲染应用 UI 的客户端代码
- 存储状态并实现应用行为的服务器代码

服务器按需作为动态 Worker 加载，并实例化为持久对象 Facet（这两项都是我们为此项目构建的功能）。该 Facet 为应用提供自己的 SQLite 数据库，与管理它的 Cloudflare OS 运行时分离。动态 Worker 使用轻量级的 V8 隔离实例，因此每个应用都可以拥有自己独立的运行时，而无需专用的服务器或容器常驻。

![BLOG-3379 5.png](/images/posts/7591263efc5b.jpg)

浏览器客户端使用 Cap'n Web（Cloudflare 的开源对象能力远程过程调用（RPC）系统）与服务器通信。可以从客户端像调用普通 JavaScript 函数一样调用服务器方法：

```
const issues = await app.listIssues({
 status: "done",
});
```

特别之处在于，Agent 也可以调用相同的方法。

因此，如果你可以自己构建工具来完成某项工作，那么当你不在时，Agent 可以使用你的工具来完成这项工作。

### 共享应用，或共享其构建方式

当你在 Cloudflare OS 中构建应用时，有两种共享方式：

- 共享应用本身，让其他人可以使用相同的状态进行实时协作。
- 共享应用的蓝图，让其他人可以创建你应用的副本。

![BLOG-3379 6.png](/images/posts/f29aad55adaf.jpg)

从蓝图实例化的应用包含原始应用的代码。但它不包含其 SQLite 数据、对话历史、凭证或已连接资源。每个新应用都从独立的状态和资源开始。

这意味着当你与团队共享应用时，他们可以使用 AI 自行修改，而无需提交功能请求并分配给你。

## 使用任何模型，并控制其成本

Cloudflare OS 可以与任何模型一起使用。每次推理调用都通过 Cloudflare AI Gateway 运行，让你的组织在一个地方决定哪些模型可用，以及每个任务应由哪个模型处理。

![BLOG-3379 7.png](/images/posts/1afe337fd016.jpg)

并非每个任务都需要最昂贵的模型。你可能不希望每天早晨使用最昂贵的前沿模型来总结未读邮件。AI Gateway 为你提供了所需的控制，确保昂贵的模型仅用于最困难的工作。

每个请求都会归属于发起请求的个人、团队或工作区。管理员可以查看推理支出的去向，设置预算和速率限制，并决定达到限制时的处理方式。

## 开源，让你可以将其变为己有

Cloudflare OS 现已可用，并且是开源的。请查看 cloudflare-os GitHub 仓库。你可以将其部署到自己的 Cloudflare 账户中，并使用自己的 Access 策略、AI Gateway 配置、数据和集成。

我们的内部部署反映了 Cloudflare 的系统、术语、策略和工作方式。你的部署应反映你所在组织的需求。

Cloudflare OS 的设计允许你自定义界面、添加内部守门人，并构建组织特定的功能，而无需更改核心产品。

我们发布了两个仓库：Cloudflare OS 核心 和 一个示例部署，后者基于我们在 Cloudflare 内部的运行方式。部署仓库在不修补核心的情况下使用核心，为配置、自定义 UI、内部集成、分析和部署流水线提供了一个场所。
