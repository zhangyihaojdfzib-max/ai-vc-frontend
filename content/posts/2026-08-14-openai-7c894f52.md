# GPT-5.6 构建者指南

来自生产环境初创公司的技术经验

## GPT-5.6 树立了性价比的新标准

GPT-5.6 模型系列使前沿级别的 Agent（智能体）性能变得大幅更实惠，同时也推进了可能性的边界。

在本指南中，我们将展示初创公司如何利用更智能的模型选择以及新的 API 控制（这些控制有助于推理连续性、多 Agent（智能体）编排和程序化工具调用），以极低的成本构建更快、能力更强的 Agent（智能体）。

## 更出色的开箱即用体验

自 GPT-5 以来，每一代模型都致力于用更少的 Token 处理更长周期的任务。GPT-5.6 延续了这一轨迹：更强的 Agent（智能体）性能、更低的成本，且对底层框架的改动微乎其微。

顶层成本效率的提升，加上在较低推理强度下准确率的提高，产生了叠加效应。例如，在 Agents' Last Exam 基准测试中，当框架保持不变时，GPT-5.6 Sol 在“低”推理强度下的表现优于 GPT-5.5 在“高”推理强度下的表现。我们在生产环境测试中也看到了类似的成功案例，初创公司报告称，通过将推理强度从之前的默认设置降低，他们在各种工作流程中实现了显著的成本节约。

## 模型选择

从历史上看，对于长周期任务，升级到推理能力最强的旗舰模型一直是最佳选择。这在很大程度上是因为这些模型在处理更长上下文和工具调用方面明显优于成本优化型模型。这种情况随着 5.6 系列的出现而改变：借助更多的测试时计算，Luna 和 Terra 通常可以达到与 GPT-5.4 和 5.5 相近的性能，但成本却低得多。

以 BrowseComp 中的任务为例：这是一个基于搜索的基准测试，用于检验模型搜索冷门事实的能力。三个月前，GPT-5.5（Extra High）在该基准测试中得分 84.36%，总成本为 33.27 美元。在发布时，GPT-5.6 Luna（Extra High）以 1.33 美元的成本实现了基本相同的性能，得分 84.04%。此后我们进一步降低了价格。阅读更多关于我们最新降价的信息。

较小的 5.6 系列模型非常适合高吞吐量工作负载、对延迟敏感的交互以及 Agent（智能体）工作流程中的重复步骤。例如，如果你经营一家法律科技初创公司，在 Agent（智能体）分析之前需要解析手写备忘录，现在你可以使用 Terra 或 Luna 进行信息提取，从而节省大量成本，而无需为整个用例使用前沿模型。

## 演进 Responses API 以构建更高效的 Agent（智能体）

除了让 GPT-5.6 开箱即用地表现更佳外，我们还为 Responses API 增加了新的原语以释放更多性能提升。我们通过三项互补的架构干预措施对 GPT-5.6 进行了端到端训练，使 Agent（智能体）能够更高效地运行：

1. 复用已完成的工作：通过允许推理在模型轮次之间持久化，并使用原生压缩来压缩长时间运行的对话，模型可以在更长的任务周期内保持工作的连贯性，而不会混淆或需要重建先前的上下文。
2. 在适当的情况下进行并行分解：使用原生多 Agent（智能体）编排，可以协调多个 Agent（智能体）跨并行工作流协作，从而更快地完成复杂任务。
3. 将确定性工作转移到代码中：使用程序化工具调用，在模型上下文窗口之外过滤、聚合和编排工具输出，将模型 Token 保留用于判断，从而降低成本和延迟，并减少上下文退化。

将这些方法结合使用，效果可能非常显著。例如，在 ARC-AGI-3 上，GPT-5.6 Sol 使用标准框架得分 13.3%。然而，在启用保留推理和压缩后，得分跃升至 38.3%——同时使用的输出 Token 减少了约 6 倍。模型没有改变，但性能却提升了近三倍。你可以在此处阅读更多关于我们 ARC-AGI-3 框架调查的信息。

## 程序化工具调用

Agent（智能体）工作流程通常涉及两类工作：

1. 需要判断力的任务
2. 主要涉及移动、过滤和组合数据的工作

当 Agent（智能体）检索 100 份文件、按日期过滤并识别相关交易时，模型不应在其上下文窗口中对每个中间结果进行推理。程序化工具调用允许 GPT-5.6 编写 JavaScript 来编排工具、并行运行独立调用，并在上下文窗口之外处理其输出。模型可以专注于需要智能的部分：运用判断力。

## 多 Agent（智能体）

对于复杂的、可并行化的任务，将行动和推理分布到多个 Agent（智能体）工作流中，可以加快任务完成速度并提高智能水平。在这些设置中，主 Agent（智能体）负责编排子 Agent（智能体）并向它们委派任务。子 Agent（智能体）并行追求各自的目标，最终将输出传回主 Agent（智能体）进行最终综合。团队可以通过在 Responses API 中启用多 Agent（智能体）来原生地利用这一功能。这也是 ChatGPT 中超能力设置的工作方式。

尽管 GPT-5.6 对合适的子 Agent（智能体）数量以及何时生成它们有很强的判断力，但多 Agent（智能体）行为是高度可控的。指导模型何时调用子 Agent（智能体），可以增加仅在额外 Token 支出能带来更好性能的情况下才生成 Agent（智能体）的可能性。

## 提示词缓存

在整个模型系列中，提示词缓存 TTL 已延长至至少 30 分钟，并且现在可以在模型上下文窗口内确定性地设置缓存断点。这使得初创公司能够显著提高其缓存命中率。

除了设置缓存断点外，继续使用适当的 prompt_cache_key 可以增加请求命中先前服务过相同前缀的同一推理引擎的可能性，从而降低延迟。
