A week ago, I finally hit my limit on my home automation misery in Aspen.

When we built this house a decade ago, we installed what was then considered a high-end home automation system. We replaced all the network gear about five years ago. While it works well overall, there are lots of little annoying things, including at least five different apps in this house alone. One of them is aSavantsystem that both Amy and I are sick of because it’s so pathetic.

But the breaking point was a little one. We have shades fromJ. Geiger, which we love.

For a while we controlled them with a few buttons on aCrestroniPhone app. A while ago, when Crestron new-and-improved everything, they removed the old app from the App Store. For some reason, it’s still on my iPhone, but not on Amy’s.

A few years ago, Savant acquired J. Geiger. Naturally, we assumed that the J. Geiger shades could be controlled by the Savant app.

So, for most of the summer, we’ve been working with multiple companies to try to be able to remotely control the J. Geiger shades. Cumulative time spent with vendors: probably at least eight hours.

No one could figure it out.

Our home automation vendor (who we like) proposed that we spend way too much money to upgrade everything in the house. When pushed, they backed off to less, but still way too much money to replace Savant withControl4, since Control4 apparently works better with J. Geiger shades. I considered that for 24 hours because we have Control4 at our house in Tucson and it works pretty well, especially our ability to control things in the house when we aren’t there.

Sunday, when I woke up, I decided this was all bullshit. All the individual pieces in our house work just fine. So, I decided to build a universal app that controlled all the devices in all our houses, would work remotely from anywhere, and had a single, web-based user-interface that could work on any device.

I call it Overwatch.

I spent all day Sunday on it and have been working on it at night the past few days. While Claude Code is my daily driver, I decided to use Fable 5 (and then 5.1 when that came out) since I expected there would be plenty of thorny things. It has been awesomely fun - and successful, other than occasionally getting downgraded off Fable 5.1 because its cyber safety filter decides that code which talks to security panels and cameras looks suspicious. When that happens it drops to Opus 4.8, which isn’t even my default - that’s Opus 5. I have no idea what made it pick 4.8. The joy of Claude randomness.

Now you may ask, “Why don’t you useApple HomeorGoogle Home?” I’ve tried. They suck. They are each another application that handles a few things but doesn’t really work. Almost nothing in my houses talks HomeKit. And Google Home is just a pathetic joke. Have you ever tried to connect anElksecurity system (apparently a favorite of my Aspen and Tucson home automation people) to either of them? Good fucking luck.

Yeah - it would have been nice if I’d used the same hardware and software everywhere. But, even then, I’d be living in a world where I’m constantly asking the vendors to change things for me.

Last year, I got our Tucson integrator to give me a login to the Control4 dealer system. I spent a few days making minor adjustments to our system and then decided I had way better things to do with my time than fight with the tragically crappy Control4 software in Parallels on my Mac. I had a similar experience withLutron.

I mean - sure - ok - if it’s 2005 this software is pretty good, but it’s 2026.

Since I have a random collection of hardware across multiple houses, I accepted that each layer was going to be different. The next few paragraphs are a boring list of vendor names, so skip ahead if you want - all you need to know is that none of these systems talks to any of the others, which isenshittificationin action. I long for the halcyon days of early Web 2.0 when it was predicted that all APIs would work with everything and data and control would belong to the user. Oh well - that didn’t happen.

Let’s start with cameras. We have fifteen of them across multiple houses from three vendors with no interest in each other: eight Google Nest, fiveUniFi Protect, and two Ring. An open source project calledgo2rtcspeaks all three and hands my browser one kind of video stream, so Overwatch only has to know go2rtc, and it cost me nothing.

The new much too expensive network was going to “fix” a bunch of things that work fine on their own. Aspen is Lutron, J. Geiger motors on a Crestron processor, Nest thermostats, anEnphasesolar inverter, Sonos, and Elk. Tucson is Elk, UniFi, and Sonos. Each has a bunch of other random things (e.g. a pool controller, garage doors).

Boulder and Basalt are the small ones - Boulder has three Nest cameras and three thermostats, and Basalt has one Ring camera. Both are entirely cloud services, which sort of makes some of it a little easier.

When I sat down to work on this on Sunday, the key design requirement was that we be able to control anything from anywhere in a web browser on a computer or an iPhone.

The magic trick to that ends up being one always-on computer in each house, withTailscaleas the bridge. I end up with everything on one private network no matter where they, or we, physically are. This gets rid of the need for cloud APIs, although they help. Tucson needed a Raspberry Pi, and Aspen needed nothing, because a Mac mini I already have running in the house does the same job.

Boulder and Basalt need nothing at all, since there is nothing local in either one to reach - they’re only cameras and thermostats, and both of those live in somebody’s cloud. I’ll put a Raspberry Pi in each place just as cheap insurance on the cloud stuff and to see if there are other devices in either place I want to control.

Next, I foundHome Assistant, an open source project that gave me a great starting point for many of the integrations. My brother Daniel, who is much better at UI than I am, found a few potential themes for me that were open source so I was able to use them as the design for the app.

I didn’t want to blow my brains out around security, so all the security needed to be living on the server in each house, behind Tailscale, so nothing with a secret runs in the browser. The browser asks the server, and the server asks the house. While I’ve had to fight a little with API keys and secrets, I’m used to that by now.

I then told Claude Code to go to work.

I’ve been systematic about each house and system type, working through them one by one. My Claude Code infrastructure (which the cool kids are calling a software factory, and the really cool kids are calling a dark software factory) is very built out, but I was curious if it would work with a completely different type of app than the ones I’ve been building atIntensityMagicandIntensityLabs. It has worked great, and Fable 5.1 has been a nice level up from both Opus 5 and Fable 5 while being surprisingly less token hungry than I expected.

Playwrightis another magic trick and with minimal effort Claude has been able to build a web interface that works nicely on a browser on a computer, phone, and tablet.

![The Aspen master bedroom on a phone - five Lutron dimmers with sliders at 100 percent, a Nest thermostat reading 71 degrees, and the Sonos speaker for that room, all in one sheet](/images/posts/d9a07deb698a.jpg)

I’m close to going from read/control only on all the devices to being able to reprogram them.

I’m comfortable this is going to work fine with Lutron as I’ve tested it enough now that I’m not worried about breaking anything. We’ll see if I can build a better UI for Sonos than the one Sonos has, although I don’t think that’ll be very hard given how fugly and confusing the current Sonos app is.
