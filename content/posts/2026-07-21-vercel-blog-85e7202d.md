AI Gateway 现已支持服务层级。服务层级让您能够针对延迟、吞吐量和每次请求的成本进行优化，以匹配您的使用场景。为交互式工作负载选择更快的层级（更少的排队、更高的 Token 吞吐量），或者为能容忍更高延迟的后台任务选择更低成本的层级。

上线之初，服务层级适用于 OpenAI 和 Gemini 模型。

服务层级适用于所有 AI Gateway API 格式：AI SDK、Chat Completions API、Anthropic Messages API、OpenAI Responses API 和 OpenResponses API。AI Gateway 会根据每次请求所使用的层级调整计费。

## 复制链接到标题层级

- default：标准处理
- priority：更快处理，成本更高
- flex：成本更低，延迟可能更高

flex：成本更低，延迟可能更高

如果未指定服务层级，请求将在 default 层级上运行。

## 复制链接到标题基本用法

在 `providerOptions.gateway` 下设置 `serviceTier`。该选项适用于所有支持服务层级的模型和提供商，因此您可以切换模型而无需重构特定于提供商的选项：

```
1import { generateText } from 'ai';2
3const { text, providerMetadata } = await generateText({4  model: 'openai/gpt-5.6-sol',5  prompt,6  providerOptions: {7    gateway: {8      serviceTier: 'priority',9    },10  },11});
```

优先级服务层级请求示例

应用的层级会在提供商元数据中返回，以便您确认处理请求的层级。当优先级请求回退到 default 容量时，或者在比较不同层级的实际延迟时，这非常有用。

服务层级基于尽力而为的原则：如果无法应用某个层级，请求将以默认费率在 default 层级上运行，只有无效的服务层级值会导致请求失败。

### 复制链接到标题按提供商控制

如果一个模型可以由多个提供商提供服务，并且您只想对其中部分提供商启用服务层级，或者希望为每个提供商配置不同的服务层级，请在提供商自己的命名空间下设置该层级。

```
1import { generateText } from 'ai';2
3const { text } = await generateText({4  model: 'google/gemini-3.6-flash',5  prompt,6  providerOptions: {7    vertex: {8      serviceTier: 'priority',9    }, 10  },11});
```

## 复制链接到标题定价

AI Gateway 会根据每次请求实际使用的层级自动应用每层级费率。如果 `priority` 请求被降级到 default 容量，计费将反映 default 费率，而非 priority 费率。
