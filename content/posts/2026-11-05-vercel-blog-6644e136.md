Vercel Schedulesis now in public beta on all plans. Run tasks on a recurring cadence or at a single point in time, in production, preview, or custom environments.

Schedules invercel.jsoncan target a private Vercel Function, an HTTP path, or a Vercel Queue topic, and schedules created at runtime target a Queue topic. Any schedule can be enabled, disabled, or run on demand without redeploying.

Define a static schedule:

```
1{ 2  "schedules": { 3    "cleanup": { 4      "schedule": "0 * * * *", 5      "function": "api/cleanup.ts", 6      "timezone": "America/New_York" 7    } 8  }, 9  "functions": { 10    "api/cleanup.ts": { 11      "experimentalTriggers": [{ "type": "schedule/v1beta" }] 12    } 13  } 14}
```

An hourly static schedule in vercel.json, targeting a private Vercel Function

Adding aschedule/v1betatrigger makes the function private. It has no public URL and only the Vercel schedule infrastructure can invoke it.

Schedules is the successor toCron Jobs. Existing Cron Jobs continue to work, and themigration guidecovers moving them to Schedules. Schedules also powerdynamic schedules in Eveand experimental scheduled tasks inNitro projects.

Vercel Schedules is billed starting at $5 per 1M runs and $10 per 1M creations on Pro and Enterprise. Hobby includes 500 schedule creations and 5,000 runs per month. Read theblog postfor more on how Schedules works, then get started with theSchedules documentation.
