Priority Projectsare now in public beta for Pro and Enterprise teams. This optional upgrade for individual Vercel projects adds bot and traffic-source signals, Page Integrity for monitoring and controlling client-side scripts and connections, and additional Firewall controls and alerts.

## Copy link to headingTraffic Sources

Priority adds Traffic Sources labels for requests from Tor exit nodes, VPNs, open or anonymizing proxies, and residential proxies. It also labels traffic flagged by abuse blocklists.

Use these labels in custom Firewall rules, analyze them in Firewall Observability, or read them from thex-vercel-waf-sourcerequest header in your application. A request can have multiple labels.

Use the Traffic Sources managed ruleset to log, challenge, or block traffic by source category. Review matching traffic before enabling blocking, since these categories can also include legitimate users.

To enable the Traffic Sources managed ruleset from the CLI, runvercel firewall managed-rulesets enable traffic-sources. This stages the change; review it withvercel firewall diff, then apply it withvercel firewall publish.

## Copy link to headingPage Integrity

Priority Projects get access toPage Integrityto monitor client-side scripts and connections, receive alerts when new scripts or connections are detected, and block unapproved resources.

Page Integrity maintains a resource inventory and usesContent Security Policy (CSP)for discovery and enforcement, without adding client-side JavaScript.

It operates in three stages:

- Detect:Discover scripts using report-only CSP headers on sampled requests.
- Review:Approve or reject scripts and record business justifications.
- Block:Enforce a CSP that blocks scripts outside the approved inventory.

## Copy link to headingFirewall controls and alerts

### Copy link to headingAnomaly alerts

DDoS alertsare available on all plans. Priority adds anomaly alerts for bot traffic and requests matching system or custom Firewall rules. Use these alerts to investigate potential attacks and unusual traffic patterns.

Configure notifications in your team’sSettings > Alerts, with delivery options including email, Slack, and webhooks.

View recent alerts withvercel alerts --since 24h. To manage alert configuration from the CLI, seevercel monitors.

### Copy link to headingOWASP Core Ruleset

On Pro, Priority lets you enable theOWASP Core Rulesetto protect against common web application attacks. Enterprise projects can already enable it without Priority.

Add it as a team default fromSecurity > Rules, or enable it for a linked project via the CLI withvercel firewall managed-rulesets enable owasp --yesfollowed byvercel firewall publish.OWASP inspectionis billed separately per inspected request and GB of inspected payload.

### Copy link to headingResponse-based rate limiting

Priority adds response conditions to therate-limit rulesavailable on all plans. Count requests toward a limit only when their responses match specified HTTP status codes or response headers. For example, count401responses from failed login attempts or404responses for missing pages, rather than every matching request.

## Copy link to headingGet started

Priority costs $200 per project per month. Enable it from your project’sFirewallorSettingspage, or with the CLI.

For the CLI, update to the latest version withvercel upgrade, then enable Priority for the project you want to upgrade:

```
1vercel project priority enable <project-id>
```

Page Integrity usage is billed separately. Its standard rate is $2 per 1,000 monitored page views, with each view covering up to 100 scripts.

Learn more in thePriority Projects documentation.
