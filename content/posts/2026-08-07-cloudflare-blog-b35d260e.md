自2020年推出以来，Cloudflare Radar一直提供全球范围内互联网流量的独到洞察。Radar从我们全球网络发布的开源数据被不同领域的各类专家使用：人权倡导者、记者、学术研究人员、网络运营商等等。

今天，作为Agents Week的一部分，Radar正在测试版推出一款新工具：Radar Researcher。

现在，如果你想用Radar的数据回答一个问题，只需用自然语言提问，就能得到带有真实交互式图表的答案，这一切都构建在Cloudflare的开发者平台上。你不再需要找到正确的页面、选择正确的筛选器，或阅读API文档来编写查询。

## 为什么我们构建Radar Researcher

在过去六年中，Radar团队一直致力于为复杂数据集提供清晰、易用、可靠的数据可视化。这并非没有挑战：我们的用户群体非常广泛，从好奇的新手到技术型网络专家都有。即便如此，我们仍尽可能多地发布从我们网络视角看到的互联网洞察：来自我们公共解析器1.1.1.1的DNS查询、来自我们全球网络的HTTP流量、从Cloudflare Speed Test收集的网络质量数据，以及更多。我们也相信开放公共数据的力量，这就是为什么你在Radar数据可视化中看到的一切都可以通过我们的免费API获取。每年我们都让越来越多的互联网变得可见。

但随着Radar的发展，处理数据的技术也在进步。AI工具正在降低专业知识的门槛：你不再需要了解数据集的结构或词汇就能从中获得有用的答案。领域专家成为协作者而非守门人。

Radar一直希望为那些不需要掌握我们整个目录及其词汇就能充分理解我们洞察的用户做得更多。（参见我们最近的博客文章，关于互联网如何应对2026年FIFA世界杯。）

我们也知道很多用户时间紧迫。例如，一位报道最新互联网中断事件的记者可能没有时间逐页搜索完美的图表来讲述他们的故事。这就是我们构建Radar Researcher的原因。

## 认识Radar Researcher

Radar Researcher的设计让获取数据变得像描述你正在寻找的内容一样简单。所有信息都通过Radar的API提供，这确保了底层LLM依赖真实数据，并能快速以你向人类表达的方式回答你的问题。

它在每个Radar页面上都可用。从页眉打开Radar Researcher面板，它会停靠在你正在查看的内容旁边，这样你可以在聊天时继续浏览。以下是一些使用示例：

- 用自然语言获取答案，附真实图表：提出问题，获得你在Radar上看到的相同交互式可视化，外加简短解释。
- 选择深度：选择简洁直接的答案或更全面的多主题报告。
- 继续分析：每次回答后，它会建议有用的后续问题。
- 从上次中断处继续：对话保存在可搜索的历史记录中，你可以固定并重新访问，也可以通过链接分享任何对话。（共享链接30天后自动过期。）
- 审计推理过程：查看LLM如何理解你的问题，它查找和查询了哪些数据集，以及它如何处理结果得出答案。
- 随心提问：输入文字、使用语音输入，或直接从Radar的搜索栏启动。

## 我们如何构建它

Radar Researcher完全构建在Cloudflare自己的开发者平台上。它展示了任何开发者都可以用来构建AI Agent的相同工具。

其核心是一个运行着 Cloudflare Agents SDK 的 Cloudflare Worker。每个会话都是一个有状态的 Durable Object，带有自己的 SQLite 数据库，因此您的聊天历史、标题和流式响应都会持久化保存。即使您在回答中途离开页面，它们也会继续存在，因为生成过程会在服务器端继续进行，并在您重新连接时恢复。“大脑”是 Workers AI，运行着像 Kimi K2.7 这样的开放模型。我们并非押注于单一模型，而是在三个不同的模型系列之间运行一个有序的回退链。如果一个模型暂时满载，请求会透明地级联到下一个模型，因此任何单一提供商的故障都不会导致 Researcher 宕机。每次调用都会通过 AI Gateway 进行日志记录、成本跟踪、缓存和安全护栏。

最有趣的部分是 Researcher 如何访问 Radar 的数据。我们并没有为 Radar 数百个端点中的每一个手动编写工具，而是使用 Code Mode 将 Agent 连接到统一的 Cloudflare MCP 服务器。模型只获得三个工具（搜索、执行和文档），并编写代码直接查询 Radar API。它搜索 OpenAPI 规范以找到正确的端点，然后执行一小段代码来获取实时数据。由于完整的 API 规范存在于 MCP 服务器上，因此 Radar 的 API 没有任何内容被硬编码到提示词中。随着 Radar 添加数据集，Researcher 无需更改代码即可使用它们。

### 从 Markdown 到真实的 Radar 图表

在此过程中有一个问题需要解决。语言模型以 Markdown 格式回答：文本、表格和项目符号。但我们不想要数字墙；我们想要的是您在 Radar 其他任何地方都能看到的丰富、交互式图表。更糟糕的是，当模型试图将数据直接写入其答案时，它往往会四舍五入、总结或截断数据，这正是您不希望从数据工具中得到的。

我们的解决方案完全将数据排除在模型的叙述之外。当 Radar Researcher 获取数据时，其代码会返回一个小的信封，将 API 路径与结果配对。然后，模型不是粘贴数字，而是发出一个轻量级的图表规范，该规范仅引用相同的路径：

```
```radar-chart
{ "type": "speedFlower", "title": "Internet speed quality — Portugal", "dataFrom": "/radar/quality/speed/summary?location=PT" }
```
```

Radar 的前端将图表的 dataFrom 与获取的结果匹配，并使用站点其余部分使用的完全相同的可视化组件进行渲染。图表始终忠实于 API，并且 Radar Researcher 可以利用我们所有的可视化词汇：时间序列和堆叠面积图、环形图、条形图、地图、直方图等。

### 一些小细节

并非所有事情都需要大模型。小而快的模型处理辅助任务：一个为每个新对话编写简短标题，另一个在每个答案下方建议后续问题。两者都在旁边运行，因此它们绝不会减慢您的实际回复速度。

Radar Researcher 也会获得一些关于此时此地的上下文。我们向其传递当前的日期和时间，以及您将在 Radar 的 IP 页面上找到的关于您连接的相同高级详细信息，例如您的 IP 位置和网络。这样，当您询问“这里的流量怎么样？”之类的问题时，它可以根据您所在的位置定制答案。

一切通过服务绑定经由 Radar 的前端（也是一个 Worker）到达您，并带有每 IP 速率限制和存储在 R2 中的可共享对话。从计算到推理再到网关、存储和数据，每一层都是 Cloudflare 的。

## 由 Agent 驱动 — 并为 Agent 就绪

Radar Researcher 展示了我们如何使用 AI Agent 来帮助人们探索我们的数据。但 Agent 故事还有另一面：当 Agent 不是我们的，而是一个在您的浏览器中运行、代表您行事的通用助手时，会发生什么？

如今，想要使用网站的 Agent 大多必须抓取页面并猜测其工作原理，这既脆弱又缓慢且容易出错。WebMCP 是一种新兴的 Web 标准，可以解决这个问题：页面可以注册一小组定义良好的工具，任何浏览器 Agent 都可以发现并直接调用这些工具，而无需对 DOM（文档对象模型）进行逆向工程。

我们已在 Radar 中添加了 WebMCP 支持，使用了该标准提供的两种风格：

- 命令式 API 允许我们在 JavaScript 中注册工具，这些工具直接调用驱动 UI 的相同代码，因此 Agent 可以直接驱动 Radar。按国家、地区、大洲或 ASN 筛选；更改日期范围；搜索页面、部分和实体（域名、ASN、IP 等）；跳转到任何部分。
- 声明式 API 通过用几个属性注释 Radar 现有的 HTML 表单来将其转化为工具，因此 Agent 可以使用 URL Scanner 扫描 URL、查找域名的报告，或测试网站的量子安全后 TLS 密钥交换支持。

这些功能中的每一个都只是驱动用户界面中已有的功能，并且是纯粹的功能增强：在没有 WebMCP 的浏览器中，这些工具就不存在，一切照旧。

这也是我们践行自身理念的一个案例。Radar 自己的 URL Scanner 会评估一个网站的 Agent 就绪程度，其中一项检查正是寻找这种 WebMCP 集成。通过自己实现它，Radar 现在通过了自身的 Agent 就绪检查，并且更重要的是，它成为了一个人类和 Agent 都可以轻松浏览的网站。
