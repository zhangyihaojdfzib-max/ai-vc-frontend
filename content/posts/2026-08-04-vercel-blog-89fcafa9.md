昨天，Next.js 团队宣布发布 Next.js 16.3，带来了更精简的预取、不可变静态资源和即时导航。作为本次发布的一部分，我们与 Next.js 团队合作，在 Vercel 上全面支持 16.3，包括更好的性能和额外的可观测性。已完成升级的应用已获得以下收益：

- **更少的预取请求**：从 16.2 升级到 16.3 的应用，预取请求平均减少 45%，部分应用减少超过 70%。
- **更低的静态资源成本**：借助不可变静态资源，升级后的应用 CDN 请求减少 17%，静态内容传输字节数减少 24%，对于频繁部署的项目，全球 TTFB 最高降低 60%。
- **大规模路由加速**：关键服务路径中的路由元数据改进，使大型站点的 p99 路由解析速度提升约 2 倍。

## 复制链接到标题平台改进

Next.js 16.3 默认启用了更精简的预取和不可变静态资源。支持这两项功能也意味着平台本身需要改变——包括静态资源的缓存方式、路由解析方式，以及生产环境中运行情况的呈现方式。

### 复制链接到标题不可变静态资源

Vercel 现在支持在 Next.js 的多次部署之间复用不可变静态资源。不可变静态资源不会出现版本偏差问题，即使项目未启用偏差保护也是如此，并且浏览器缓存可以在重新部署后继续生效。由于 Next.js 使用基于查询参数的偏差保护，这一改动使 CDN 请求减少 17%，静态内容传输字节数减少 24%。同时，由于未变更的资源无需重新上传，部署完成速度平均提升 30%。在 Next.js 16.3 中，不可变静态资源默认启用。

Next.js 16.3 在公共路径 `/_next/static/immutable/*` 下输出不可变的、基于内容寻址的静态资源。Vercel CDN 使用此前缀来区分不可变静态资源与其他静态资源。

如果你是一个框架作者，并希望在自己的工具链中实现这一功能，请参阅 Build Output API 文档中的不可变静态文件部分。

### 复制链接到标题大规模路由加速

Next.js 16 引入了一项优化：应用的公共部分会被预取一次，并在多次导航之间复用，而不是为每个链接重新获取。为了实现这种复用，每个共享片段都必须能够单独获取，因此 Next.js 为同一个应用生成了更多的路径。

这些额外的路径在平台侧不断累积。像 Next.js 这样的框架通过 Build Output API 部署到 Vercel，框架为每个路径生成一个描述如何服务该路径的元数据文件，例如其预渲染配置。Vercel CDN 在每个请求的路径中读取该元数据，因此每次查找必须在几毫秒或更短时间内完成，并且 CDN 会缓存元数据以保持在预算之内。在全球范围内，这相当于每秒 500 万次查找。随着 Next.js 16 应用发布更多路径，缓存中的条目增多，命中率下降，我们看到大型应用的 p99 TTFB 有所增加。

为了解决这个问题，我们改进了服务路由元数据的层级，使其速度提升约 2 倍，缓存未命中减少约 10 倍。我们不再将每个片段的元数据作为单独的缓存条目存储，而是将条目合并为 JSONL 格式的分片，并围绕这些分片优化了进程内和远程缓存。更少但更大的条目意味着更高的命中率，而 JSONL 格式仍然让 CDN 能够快速在分片内找到正确的条目。

我们还收到了用户对增量静态再生成（ISR）重新验证更多可见性的需求。ISR 可观测性页面现在突出显示基于时间的和按需的重新验证，我们公开了缓存原因和 ISR 写入利用率，并发布了一份关于如何减少 ISR 重新验证的指南。

今天，我们还推出了对部分预渲染（PPR）的可观测性支持。PPR 立即提供页面的静态部分，然后流式传输动态内容，例如个性化或实验内容。在底层，它将 ISR 和 Vercel Functions 整合到一个系统中，使应用同时受益于两者。使用 Cache Components 的 Next.js 16 应用在部署到 Vercel 时会自动获得 PPR。

在 Vercel 仪表板中，PPR 可观测性页面显示哪些请求正在提供静态内容、动态内容，或两者的组合。使用它来确认静态外壳正常工作，捕获已回退为完全动态的路由，并查看函数何时运行。

如果需要深入排查，可以点击进入 ISR 或 Functions 可观测性页面，查看缓存重新验证或函数执行的详细信息。
