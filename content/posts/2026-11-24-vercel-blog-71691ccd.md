Withflags@4.5.0, projects on Vercel can useFlags Explorerand precompute withoutFLAGS_SECRET. That cuts out a setup step for new projects and removes the need to keep a shared secret in sync across microfrontends.

Vercel signs Flags Explorer discovery requests and overrides, and the SDK encrypts flag values shown in the Vercel Toolbar with Vercel’s public key.

Existing projects keep usingFLAGS_SECRETwhile the environment variable is set or the secret is passed in code. Upgrading alone doesn't switch them to Vercel-managed keys. To use Vercel-managed keys for these features, remove the environment variable and any code that passes the secret explicitly. For local development, runvercel env pull.

Precomputed codes created without a secret work only in the deployment that created them. Precompute without a secret requires Vercel system environment variables, which are enabled by default. Prebuilt deployments and codes that must work across deployments still need a secret; useFLAGS_PRECOMPUTE_SECRETif only precompute needs one. If you use a build cache, see theprecompute documentationfor the required configuration.

Learn more in theFlags SDK documentation.
