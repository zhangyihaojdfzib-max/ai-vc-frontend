今天，我们很高兴地宣布对Cloudflare AI Search进行一系列开发者体验改进，让您能够开箱即用地轻松管理搜索解决方案。此前，您需要自行拼接Cloudflare各种基础组件（Workers AI、AI Gateway、Vectorize、R2、Browser Run），但现在，AI Search可以自动完成这些工作，而且效果更好。我们的目标是赋予您的Agent（智能体）自己的搜索引擎，让它们能够轻松找到数据，为自己和人类用户提供更好的答案。

我们还将分享AI Search定价的早期预览，让您了解其扩展方式。我们的定价模式既可预测又可扩展：使用默认模型时，嵌入和重排序完全免费，无需担心Token数量的预测问题。

在AI Search中，用户现在可以：

- **为您的Agent索引数据集合**：让结构化与非结构化数据轻松可供Agent使用，从单个文件到您拥有的网站均可。（目前，数据源必须是您Cloudflare账户中的区域，但更多验证所有权的方式即将推出。）
- **为您的网站跳过站点地图**：此前，AI Search要求网站具备站点地图才能使用网站集成。现在，您可以选择“发现”解析选项，将没有站点地图的网站添加为数据源。
- **获取跨命名空间搜索的单一公共端点**：当您在命名空间上启用公共URL时，可以获得一个`/search`和`/mcp`端点，无需身份验证即可一次搜索多个实例或网站，方便与客户共享。
- **为公共端点配置自定义域名**：您现在可以在公共URL上添加自己的域名，从而为您的`/search`和`/mcp`端点打造品牌形象（例如，`search.example.com/mcp`）。您还可以添加Cloudflare Access来创建私有搜索实例。
- **通过AI Search插件为基于EmDash构建的网站添加语义搜索**：如果您的网站运行在EmDash（我们的开源CMS）上，AI Search插件可以为您的网站内容添加语义搜索功能。
- **预览AI Search的新定价模式**：我们希望定价可预测且能随您扩展，因此已将嵌入和重排序的成本纳入考量：当您使用Workers AI目录中的特定模型时，这些功能完全免费。

## AI Search的实际应用：驱动全新的Cloudflare Dev Stack MCP

我们在新的Cloudflare Dev Stack MCP中使用了AI Search，您现在就可以在我们的AI Playground中试用。它为编码Agent提供来自Cloudflare开发者生态系统的、带引用的最新文档，让它们能够基于最新的功能和修复进行构建，而不是依赖过时的训练数据。

以下是我们利用AI Search现有功能构建它的方法：

### 1. 索引每个内容面

我们为每个Cloudflare拥有的内容面创建了一个AI Search实例：文档、博客、API文档、社区、Astro、Vite、Vitest、Hono、Replicate、OpenNext。（这些网站均为Cloudflare所有。）

它们跨越不同的域名，但由于Cloudflare拥有这些网站数据，AI Search能够将它们视为一个整体，并以相同方式摄取。将AI Search指向一个或一组网站，它就会自动处理爬取、摄取、嵌入和检索。创建实例只需一条命令，对于没有站点地图的网站，您可以添加`--parse-type discover`参数，通过跟踪链接来发现页面（由Browser Run的/crawl功能驱动）：

```
npx wrangler ai-search create cloudflare-community \
  --namespace dev-stack \
  --source https://community.cloudflare.com \
  --type web-crawler \
  --parse-type discover
```

### 2. 将多个实例合并为一次搜索

现在到了有趣的部分：跨全部10个实例回答单个查询。有两种方法可以实现。

**方案A：在Worker中实现（我们为Cloudflare Stack MCP采用的方式）**

我们将命名空间绑定到一个Worker，创建了一个远程MCP服务器，并在全部10个实例之间进行了一次多实例调用。我们选择这条路径是因为我们要将堆栈搜索集成到Cloudflare的MCP服务器中，因此它作为工具与Agent已连接的Cloudflare工具一起发布。

在`wrangler.jsonc`中的绑定配置：

```
{
  "ai_search_namespaces": [
    { "binding": "AI_SEARCH", "namespace": "cloudflare-stack" }
  ]
}
```

然后，一个工具进行一次调用，该调用会分发到您指定的所有实例：

```
// 一个工具，一次调用，同时搜索命名空间中的所有内容面。
context.registerTool(
  'search_dev_stack',
  {
    description: 'Search current docs across the Cloudflare stack.',
    inputSchema: z.object({ query: z.string() }),
  },
  async ({ query }) => {
    const res = await context.env.AI_SEARCH.search({
      query,
      ai_search_options: {
        instance_ids: ['developers-cloudflare-com', 'astro', /* ...every surface */],
        retrieval: { max_num_results: 10 },
        reranking: { enabled: true },
      },
    })
    // res.chunks 返回时带有引用来源，并标记了它们来自哪个实例。
    return { content: [{ type: 'text', text: format(res.chunks) }] }
  }
)
```

**方案B：开启公共端点（无需编写代码）**

如果您完全不想编写Worker，可以在命名空间上启用公共URL。您立即就能获得`/search`和`/mcp`端点，无需身份验证，也无需部署任何内容，即可查询所有实例。

当您像我们一样将搜索集成到现有应用或MCP服务器时，请选择Worker方案。或者，当您只想一键获得可共享的搜索端点时，请选择公共端点方案。

### 3. 打造品牌并加强安全

公共端点带有默认的公共URL，但您可以在其上配置自己的自定义域名来打造品牌形象（例如，`search.example.com/mcp`）。

如果搜索需要设为私有，请在域名前添加Cloudflare Access。端点现在需要登录才能访问，因此只有经过授权的人员（或Agent）才能查询。

## AI Search尊重所有爬虫策略

AI Search在后台由Browser Run/crawl驱动，但更进一步，它使用自己的爬虫身份来标识自己：Cloudflare-AI-Search。与Browser Run一样，它遵循robots.txt，使用不可变的公共用户代理标识自己，并尊重网站设置的所有爬虫控制策略。
