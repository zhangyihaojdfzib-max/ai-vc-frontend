# Does Your Model Run on AWS Trainium? Look It Up

In aprevious post, we introduced TorchNeuron, the native PyTorch backend for AWS Trainium (thetorch-neuronxpackage). With it, Transformers runs its own modeling code on Trainium, as it does on any other device, so any Transformers model on the Hub may run. Which ones actually do?

Thetorch-neuronx model supportSpace answers that question for the most popular models on the Hub. It tells you whether a model runs unmodified on Trainium, and gives you the script to run it yourself.

## Look up a model

The Space opens on theSelectedview: our own selection of models picked among the top models on the Hub by downloads and by trending score. Each row gives the result, the number of Trainium cores the model is sharded over, the wall time of the run (compilation included) and the peak device memory.

To look up a given model, switch to theTrendingorDownloadsview and type part of its name. These views follow the Hub's own rankings, one task at a time, whether a model was tested or not. When a model was left out on purpose, the Space tells you why (most of the time it was not prioritized, sometimes it is truly incompatible). You can also pick the versions of the Neuron compiler (neuronx-cc) and of Transformers to look at.

At the time of writing, only Transformers models are tested, and our selection is limited totext-generationandimage-text-to-textmodels. We plan to expand to diffusers, sentence transformers, and other transformers tasks.

## Run it yourself

Select a model to see how to run it. The Space lists the Neuron stack the model was tested on, the packages to install on top of it, and therun.pyscript that ran. The script follows the recipe of theTorchNeuron announcement: it loads the model withfrom_pretrained, sharded when it needs to be, then generates with a static cache andtorch.compile(backend="neuron").

On a Trainium2 (trn2) instance with that stack, for example in theAWS Neuron Deep Learning Container, install the packages, then run:

```bash
python3 run.py

```

No need fortorchrun: the script launches its owntorch.distributedranks when the model is sharded.

A first run starts by compiling the model's graphs. To skip that step, copy the graphs the same compiler built during the test, from the publicNEFF cachebucket. The Space gives you the command, with the right compiler version:

```bash
hf buckets sync hf://buckets/aws-neuron/torch-neuronx-neff-cache/neuronxcc-<version> /tmp/neff_cache

```

## What "runs" means

Each test loads the model on atrn2instance, sharded over the smallest number of Trainium cores that can hold its weights. Most models are sharded with tensor parallelism. Mixture-of-experts models without a tensor-parallel plan use expert parallelism only. The test then generates 32 tokens and checks them. On a single core, the tokens are compared with those of a CPU run of the same checkpoint. When the model is sharded, a small judge model checks that the text is fluent English.

At the time of writing, only models that fit on 4 Trainium2 devices are tested, which means 16 cores at most. APASSsays nothing about throughput, or about longer generations.

## The results are a dataset

Everything the Space shows comes from the publicaws-neuron/torch-neuronx-model-supportdataset, with one Parquet file per pair ofneuronx-ccand library versions.

Each row holds a model's result, the error when it failed, the versions of the whole stack and therun.pythat ran. You can query it directly:

```python
import pandas as pd

df = pd.read_parquet("hf://datasets/aws-neuron/torch-neuronx-model-support/data")
df[df.model_id == "Qwen/Qwen3-0.6B"][["neuronx_cc", "library", "library_version", "neuron_cores", "result"]]

```

Thedataset cardgives the exact meaning of each result.

Next time you wonder whether a model runs on Trainium,look it up.
