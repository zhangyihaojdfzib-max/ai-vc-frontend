Knewton并非一个易于解释的产品。它分析海量数据，实时调整学生在各学科的学习计划，判断他们的学习方式，并提出最佳辅助方案。这是一种科技体验，将庞大复杂的事物化繁为简，仿佛魔法般轻松。

过去四年里，Robbie Mitchell和他的团队一直在创造各种方式来描述一套全新的教育可能性。作为Knewton的市场与传播负责人，他不仅帮助塑造了公司的形象，还主导了其市场营销策略，以获取最大的增长动力。如今，他将市场团队运营得像组织内部的一个独立代理机构，拥有自己的工程师——他强烈推荐这种模式给那些需要快速完成大量工作的小团队。目前效果甚佳。Knewton已与教育界的巨头如Pearson、Houghton Mifflin和Microsoft达成了重大合作。

在这次独家专访中，Mitchell解释了他如何设计内部代理模式，这一模式如何赋予公司竞争优势，以及为什么其他初创企业也应考虑效仿。

**从初创期就投资市场营销**

许多初创企业——尤其是那些技术驱动型的——资源紧张，在产品定型之前往往不优先考虑或投资于市场营销。Mitchell认为这是一个错误，产品和市场营销应该同步发展。

“如果你不先尝试向人们推销，怎么知道你在构建的东西是大家需要的？”Mitchell说。“你需要尽快验证产品市场契合度，而唯一的方法就是在构建技术的同时明确价值主张。”

这需要搭建一个敏捷的网站，不断测试新的文案以了解哪些能引起潜在客户的共鸣，以及良好的设计让你立即展现出专业形象。根据市场对这些资产的反馈，你的初创企业可以更容易地挑战自身假设并验证产品路线图。

基于他在Knewton的早期经验，Mitchell和同事们将市场团队建设为一个独立、自给自足的代理机构，拥有自己的设计和工程专家，专门根据市场营销需求进行执行和迭代。

“市场营销就是不断测试什么有效、什么无效，”Mitchell说。“所以你可以边构建产品边测试，或者先构建产品然后坐等市场团队追赶上来。”

为了实现代理模式，Mitchell需要做到以下几点：

- 获得高管的支持。
- 用有限的资源打造一支高绩效团队。
- 制定并执行一个独立的计划，以推动整个公司的发展。

**说服领导层**

作为初创企业的市场负责人，你能做的事情很大程度上取决于创始人。提议将市场营销与公司其他设计和工程部门分离，即使不算激进，也可能引发争议。但这是必要且有效的，原因充分。

由于市场营销很容易被视为事后考虑，专门负责营销的团队常常发现自己需要请求别人帮忙才能完成任务。例如，如果需要在网站上构建用户获取功能，或为媒体或合作伙伴会议制作原型，他们必须说服产品经理、设计师或工程师参与项目。要让这些事项进入公司路线图本身就很难，更不用说持续迭代和微调使其真正发挥作用了。

“对于市场营销来说，你需要在这些领域获得持续支持，”Mitchell说。“很多工程师和产品负责人不喜欢处理营销问题，因为需要不断调整，所以你真的必须找到合适的人。但即使找到了，也不能保证他们有时间或得到许可来帮助你。”

所以，一方面，获取合适人才受到限制。另一方面，市场营销有着庞大而全面的工作要做——从建立品牌到吸引用户，从优化注册流程到分析每一分钱投入的效果。如果你是市场负责人，量化地展示这种不平衡可以赢得创始人和其他高管的支持。反直觉的是，另一件要做的事情是展示处理营销事务有多么令人头疼（因此为什么需要专属资源）。

“在分离之前，我们不断打扰每一个和我们沟通的人，”Mitchell说。“产品经理、设计师、工程师——他们都想交付功能、打个勾然后继续前进。我们从未停止衡量和改进功能，所以他们对我们的能力存在固有的不信任。”这完全是另一种思维方式。

由于对测试和优化的执着，市场营销并不总是适合标准的时间表。Mitchell的团队发现他们需要按照自己的节奏和不同的监督方式工作。要实施真正出色的营销策略，他们需要在追求大目标的同时应对每天出现的小危机和机遇。

“要快速应对事情，唯一的方法就是大家步调一致并拥有所需工具。否则你会像无头苍蝇一样乱转，”Mitchell说。

最终，Knewton的领导层同意尝试新方法，市场营销团队从自主管理网站开始。同时，他们引入了一组核心技术专家，这些专家既对开发和设计工作感兴趣，又能快速交付。但最终是如何建立起这种信誉的呢？

Mitchell可以指出具体的里程碑事件，巩固了团队在公司中的地位。其中最重要的是几年前Knewton网站的重新设计和迁移。从静态HTML转向WordPress，网站还需要定制化以配合公司的增长。Mitchell的精英团队设计并构建了一个托管和部署框架，既能快速开发又不会导致整个网站崩溃。最终，他们将WP-Stack作为开源工具发布，吸引了更广泛的开发者社区。

“这个项目足够大，让我们在技术对话中占据了一席之地，”Mitchell说。“我们赢得了产品团队的信任，并有力地论证了为什么我们需要更多支持。”

“抓住这类让市场营销发光的机会是一回事，但之后你必须持续展示价值，”他说。自网站重新上线以来，Mitchell和他的团队交付了许多附加功能、一个面向API开发者的文档门户，以及帮助教育出版商充分了解Knewton能为他们产品做什么的可视化工具。

“我们希望做的工作与公司的愿景紧密对齐，”他说。“当我们获得了所需的设计和工程资源后，扩展影响力变得容易得多，整体士气也更高了。”

**边飞边造你的内部代理机构**

Mitchell团队每天面临的最大挑战之一是公司增长的速度。成为全球技术提供商既昂贵又耗时。为了适应这种规模，品牌和营销策略的演变需要不断变化。

他们利用自身编辑优势所做的其中一件事是重新调整Knewton的内容管理系统。在这个过程中，Mitchell发现团队内部的技术人才是市场营销成功的关键推动因素。这不仅仅是找别人来做工作；他鼓励团队中的每个人（包括他自己）掌握相关技术技能。

“我必须熟悉版本控制、前端模板、部署系统——实际上是一整套用于支持和服务我们社区的工具，这带来了巨大的改变。”他说。与此同时，他尽可能地在能招人的地方扩充了团队。

米切尔也是从小处着手，以证明这条路行得通。“起初我们聘请的是远程工作的兼职设计和开发承包商。后来我们有了一位全职留用的艺术总监和一位工程师——仍然是远程工作。最终我们把所有工作都转为内部完成。”

如今，Knewton 的营销团队包括一个覆盖从印刷品到交互式可视化的设计团队、一名全栈开发者和一名编辑，此外还有负责传播、用户获取和内容营销的通才，以及按需聘请的自由职业者。

“关键在于找到那些从一开始就愿意投身营销工作的人。”米切尔说，“科技圈里很多设计师和开发者都有过与营销团队合作的不愉快经历——他们觉得自己会被困在做横幅广告之类的事情上。”

为了改变这种看法，米切尔表示，重要的是详细说明营销团队承担的并非视觉和文案导向的职责，并且要从最难的问题入手。比如构建一个所有客户关系都依赖的门户网站，这对非常有才华的程序员和设计师来说很有吸引力。同时，他向人们保证，他们将在一个人数精简、自给自足的团队中工作，并拥有在其他地方无法获得的自主权。

“当你的团队没有庞大的基础设施、没有项目经理等支持时，你需要能够自己把事情从头到尾完成。”米切尔说，“这就是为什么我喜欢与那些曾经自己创业或直接与客户打过交道的人共事。他们天然具备关于需要做什么的知识。”

为了找到这样的人才，营销团队在很大程度上不得不从公司外部寻找，而且面试过程是经过精心设计的。例如，米切尔会给设计和开发候选人一个（带薪的）测试项目，针对他们将要担任的岗位量身定制。他们能否重新设计现有网站上的某个区域，以改变其重点或提高参与度？他们能否创作出符合品牌风格指南的连贯作品？他们在这个过程中是否会提出好的问题？

他建议通过以下问题来识别“产品经理”特质，并找到懂技术的营销候选人：

- 他们在用户想要的功能与设计师或开发者合理的工作范围之间充当翻译的能力如何？
- 他们能否深入思考功能请求的影响？“我们在寻找那些知道自己不能像许多营销人员那样简单要求把东西做出来的人。他们必须知道如何将自己的目标转化为直接、具体、以结果为导向的请求，并预见到未来的开发需求。”
- 他们与团队中不属于自己职能领域的人协作的能力如何？

最后一个问题对米切尔来说尤为重要。在一个从开发者到写作者都有的团队中，他们需要知道如何以独特的方式合作，而这种合作只有通过开放和真诚的兴趣才能实现。“一个有凝聚力的营销策略需要集思广益——在这种模式下，大多数参与者看起来并不像传统的‘营销人员’。”他说。

随着这些招聘优先事项在团队成长过程中积极塑造着团队，米切尔得以用跨职能专家充实他的内部团队，这些专家能够高效地梳理优先级并分配资源。“让所有这些类型的人保持同步并不常见，但绝对是可以做到的。我们每天都在这样做。”

**在没有地图的情况下航行**

“我们团队以快速响应全公司的需求而闻名。比如当一笔大交易即将达成，而合作方想要深入了解 API 文档时，我们能够设计和构建一个从我们的实时 API 中提取数据、添加编辑层并安全地展示所有内容的东西。”（其中一些工作最终也被开源了。）

随着公司最近 5100 万美元的融资推动其向欧洲扩张并建立更多国际合作伙伴关系，这种情况将变得更加常见。这使得这家公司不像一家需要跑得更快、做得比想象中的人数所能承载的更多的小型初创公司。

对于营销领导者来说，要想快速处理项目，他们必须：

- **喜欢构建东西。** 对流程的每个部分都保持好奇。花时间自己学习必要的技能，或者至少理解它们。
- **充当事实上的产品经理。** 促进想要构建功能的人和实际构建功能的人之间的建设性互动。
- **认识到被动规划** 可以带来一些最酷的项目。

Knewton 的营销团队不得不学会随着时间的推移变得敏捷。最初，该公司直接向消费者提供软件。随着它转向企业模式，其信息传递、定位和营销策略也必须相应调整。

这也是清晰的路线图从未成为米切尔团队指导力量的原因之一。相反，他们跟踪在任何特定时间对公司目标最重要的项目——始终允许自发替换。

“放下一切、齐心协力应对的方式并不总是有趣，但我们发现，这是应对这些时刻的最佳方式，而不会让其他人完全脱离那些有很多依赖关系的路线图项目。”

他们还会保留一份单独的愿望清单，列出在难得有空闲时间窗口时想要添加的功能和要运行的测试。这样，当有时间时，他们就能抓住机会进行渐进式改进。

“这并不是非常科学。”他说，“我们做的事情是那些我们知道对业务有价值的事情。我们负责将它们完成，然后展示它们带来了什么成果。”
