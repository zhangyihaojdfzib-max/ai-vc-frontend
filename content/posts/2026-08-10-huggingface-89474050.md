# Meta 携 Muse Glimmer 回归：本地化、智能体化、多模态，且开源！

来自开源大语言模型领域 OG 们的好消息！今日发布的 Muse Glimmer 是 Meta 的新多模态模型，专为本地智能体用例而设计。它从 Muse 蒸馏至 30B 参数，并以 Apache 2.0 许可证发布，非常适合本地部署以保护隐私、降低成本，或仅仅用于技术探索。它面向隐私敏感型应用，如编码、文档分析、个人助理，以及类似 Claw 或 Hermes 的配置。

为了庆祝，我们在 transformers、llama.cpp、vLLM、Inference Endpoints 及其他库中提供了 Meta 的 Day-0 支持。我们构建了一些很酷的东西，并在本博客中解释我们的发现。

## 架构

Muse Glimmer 是一个稠密的 30B 参数模型，包含：

- 用于视觉的 2B ViT 风格编码器（感知编码器）
- 28B 参数文本解码器

除了主要的 VLM 之外，还有一个基于 DFlash 实现的推测解码草稿模型。该模块的使用是可选的，它可以用一定的内存成本换取更快的生成速度。我们发现这个草稿模型特别适合结构化内容生成，例如编码。

### 文本解码器

语言模型使用以下架构组件：

- 混合注意力：在三个滑动窗口层（2,048 个 Token）之间交替，使用旋转位置嵌入，随后是使用全注意力和 NoPE（无位置嵌入）的第四层。因此模式为（SWA、SWA、SWA、Full），重复 13 次，共 52 层。这使得模型能够通过 RoPE 保留相对顺序和距离信息，并通过 NoPE 全局保留信息。
- 门控分组查询注意力：每个键值头由 16 个查询头共享，这将 KV 缓存内存减少了 16 倍，并使生成更快、更便宜。
- 带有额外查询缩放的 Q-K 归一化：在计算注意力之前，Muse Glimmer 对每个查询和键头应用 RMS 归一化，以保持注意力 logits 稳定。之后，查询乘以一个缩放因子，以在归一化后设置目标 logit 缩放。额外的查询缩放行为类似于 softmax 级别的逆温度。

### 感知编码器

Muse Glimmer 使用一个图像编码器来处理图像和视频。与其他 VLM 中使用的相对较小的视觉编码器不同，这是一个相当大的 2B ViT 类模型，设计遵循感知编码器架构。感知编码器此前由 Meta 推出，作为各种下游空间和多模态任务的主干。编码器将图像分块为 2 帧 x 3 通道 x 14 x 14 的形状，并通过线性层进行投影。然后，从学习到的位置表中插值的绝对位置嵌入被添加到这些嵌入中。接着，这些被发送到由 50 层和 GELU MLP 组成的视觉塔。与语言模型类似，注意力模式由三个窗口注意力层和一个全注意力层组成。在注意力层内部，对查询和键应用 2D RoPE。

在 Transformer 之后，像素洗牌将相邻的 2x2 空间 Token 组连接起来，将图像 Token 数量减少 4 倍，而不会丢弃其通道。合并后的特征随后被投影到文本解码器的共享嵌入空间。

视频逐帧通过相同的编码器，其中每帧被转换为补丁（形状为 [batch, temporal groups, grid height, grid width, 2 frames, 3 channels, 14, 14]）。处理器目标为每秒 2 帧，并将片段限制为从视频中均匀采样的 96 帧。处理器创建带时间戳的视频占位符，将文本与帧交错，例如“Time: 0.0s <|video|> x N”，其中最终的视频嵌入在最终投影层之前被替换。

## Transformers

升级 transformers 到最新版本以使用 Muse Glimmer。

```bash
pip install --upgrade transformers accelerate

```

Muse Glimmer 在 transformers 中提供 Day-0 支持，包括主模型和推测解码草稿模型。您可以使用 `AutoModelForMultimodalLM` 和 `AutoProcessor` 类来加载模型和处理器。

```py
from transformers import AutoProcessor, AutoModelForMultimodalLM

MODEL_ID = "meta-models/Muse-Glimmer-30B"


processor = AutoProcessor.from_pretrained(MODEL_ID)
model = AutoModelForMultimodalLM.from_pretrained(
    MODEL_ID,
    dtype="auto",
    device_map="auto"
)

```

相同的代码片段可以在 NVIDIA (CUDA)、AMD (ROCm) 和 Intel (XPU) GPU 上无修改运行，`device_map="auto"` 将模型放置在可用的任何加速器上。

### 纯文本推理

加载模型后，您可以按如下方式使用它进行纯文本推理。

```py
from transformers import AutoProcessor, AutoModelForMultimodalLM

MODEL_ID = "meta-models/Muse-Glimmer-30B"


processor = AutoProcessor.from_pretrained(MODEL_ID)
model = AutoModelForMultimodalLM.from_pretrained(
    MODEL_ID,
    dtype="auto",
    device_map="auto"
)


messages = [
    {"role": "user", "content": "Write a short joke about saving RAM."},
]


inputs = processor.apply_chat_template(
    messages,
    tokenize=True,
    return_dict=True,
    return_tensors="pt",
    add_generation_prompt=True,
    reasoning_strength="low"
).to(model.device)
input_len = inputs["input_ids"].shape[-1]


outputs = model.generate(**inputs)
response = processor.decode(outputs[0][input_len:], skip_special_tokens=False)
print(response)

```

### 多模态工具调用

Muse Glimmer 支持多模态工具调用，以下是具体操作方法。在下面的示例中，我们要求模型根据图片中的城市来调用天气工具。

```py
import json
import re
from transformers import AutoProcessor, AutoModelForMultimodalLM

MODEL_ID = "meta-models/Muse-Glimmer-30B"


processor = AutoProcessor.from_pretrained(MODEL_ID)
model = AutoModelForMultimodalLM.from_pretrained(
    MODEL_ID,
    dtype="auto",
    device_map="auto"
)

tools = [
    {
        "type": "function",
        "function": {
            "name": "weather.get",
            "description": "获取某个城市的当前天气。",
            "parameters": {
                "type": "object",
                "properties": {
                    "city": {"type": "string"},
                },
                "required": ["city"],
            },
        },
    }
]


messages = [
    {
        "role": "user",
        "content": [
            {"type": "image", "image": "https://huggingface.co/datasets/merve/vl-test-suite/resolve/main/SF.png"},
            {"type": "text", "text": "我要去这张图片里的城市。我应该穿什么衣服？"},
        ],
    },
]

inputs = processor.apply_chat_template(
    messages,
    tools=tools,
    tokenize=True,
    return_dict=True,
    return_tensors="pt",

```

## Llama.cpp

Muse Glimmer 在发布首日即支持 llama.cpp。Meta 已在此仓库中发布了校准后的量化版本，Unsloth 也正在发布优化后的量化版本。同时支持 DFlash 投机解码。你可以使用预构建的 llama 二进制文件来启动 llama 服务器或 CLI。要安装 llama.cpp，请运行：

然后你可以按如下方式启动服务器。


服务器启动后，你可以访问 localhost:8080 与内置 WebUI 进行对话。

## 投机解码

DFlash 使用轻量级块扩散草稿模型，在解码阶段提供相同输出的同时带来额外加速。Transformers 和 llama.cpp 在 Muse Glimmer 发布首日即支持 DFlash 草稿模型。

下面你可以看到投机解码在实际场景中如何加速生成。视频左侧为启用 DFlash 的 llama.cpp webui，右侧为常规生成。

### 使用 Transformers 进行投机解码

你可以按如下方式加载草稿模型和主模型，并在推理时像使用基础模型一样额外添加一个参数（见后续代码片段）。

```py
import torch
from transformers import AutoProcessor, MuseGlimmerAssistantModel, MuseGlimmerForConditionalGeneration

model_id = "meta-models/Muse-Glimmer-30B"
assistant_model_id = "meta-models/Muse-Glimmer-30B-assistant"
target = MuseGlimmerForConditionalGeneration.from_pretrained(model_id, dtype=torch.bfloat16, device_map="auto")
assistant = MuseGlimmerAssistantModel.from_pretrained(assistant_model_id, dtype=torch.bfloat16, device_map="auto")
processor = AutoProcessor.from_pretrained(model_id)

messages = [
    {
        "role": "user", "content": [
            {"type": "image", "url": "https://huggingface.co/datasets/merve/vl-test-suite/resolve/main/SF.png"},
            {"type": "text", "text": "这张图片中显示了什么？"}
        ]
    }
]

inputs = processor.apply_chat_template(
    messages,
    tokenize=True,
    return_dict=True,
    return_tensors="pt",
    add_generation_prompt=True,
    reasoning_strength="low"
).to(target.device)
input_len = inputs["input_ids"].shape[-1]

outputs = target.generate(
    **inputs,
    assistant_model=assistant,
    speculation_type="dflash",
    do_sample=True
)
response = processor.decode(outputs[0][input_len:], skip_special_tokens=False)
print(response)

```

### 使用 llama.cpp 进行投机解码

你可以使用以下命令启动 llama 服务器。`--spec-draft-n-max` 参数控制 DFlash 在每次投机解码步骤中提议的未来 Token 数量。Muse Glimmer 的 DFlash 模型以 16 的块大小进行训练，即 1 个锚点 Token 加 15 个提议 Token，因此任何大于 15 的值都会被截断为 15。

```bash
llama serve -hf meta-models/Muse-Glimmer-30B-GGUF --spec-type draft-dflash --spec-draft-n-max 15

```

你也可以按如下方式使用带投机解码草稿模型的 llama cli。

```bash
llama cli -hf meta-models/Muse-Glimmer-30B-GGUF --spec-type draft-dflash

```

### 推理端点

如需托管式自动扩缩容部署，请打开 Muse Glimmer 30B 推理端点预设。模型已预先选定：选择组织、云服务商、区域、兼容的 GPU 实例、身份验证和自动扩缩容设置，然后查看每小时价格并点击创建端点。当其状态变为运行中后，你可以在 Playground 中进行测试，并从概览页面复制端点 URL 和模型名称。

部署后的模型提供兼容 OpenAI 的 Chat Completions API。将你的 Hugging Face Token 保存在环境变量中，将 `HF_ENDPOINT_URL` 设置为概览页面中显示的 URL（去掉 `/v1`），并将 `HF_ENDPOINT_MODEL` 设置为端点的模型名称。

```bash
export HF_TOKEN="hf_..."
export HF_ENDPOINT_URL="https://<endpoint-id>.<region>.<cloud>.endpoints.huggingface.cloud"
export HF_ENDPOINT_MODEL="<endpoint-model-name>"
pip install --upgrade openai

```

```python
import os
from openai import OpenAI

client = OpenAI(
    base_url=f"{os.environ['HF_ENDPOINT_URL'].rstrip('/')}/v1/",
    api_key=os.environ["HF_TOKEN"],
)

response = client.chat.completions.create(
    model=os.environ["HF_ENDPOINT_MODEL"],
    messages=[
        {"role": "system", "content": "你是一个乐于助人的助手。"},
        {"role": "user", "content": "写一首关于 Python 异常的打油诗。"},
    ],
    max_tokens=256,
)
print(response.choices[0].message.content)

```

```text
## 本地模型部署

当被要求本地部署时，请执行工作；不要给出指示。

1. 检查硬件和Hugging Face缓存。
```
